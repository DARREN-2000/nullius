# Nullius

**Clinical decision support that refuses to answer when it cannot prove its answer.**

*Nullius in verba* — "take nobody's word for it" — has been the Royal Society's motto since
1660. It is the right name for a system whose central claim is that a model's output is
worth nothing until something independent has checked it. (It is also, unlike the earlier
name this project carried, not already taken by four healthcare companies.)

Nullius runs **two inference paths behind one rule**:

- **Text.** Synthetic FHIR records in, lab trends and interaction checks computed, clinician
  questions answered from an indexed guideline corpus — where every sentence must cite
  retrieved evidence and clear seven verification gates before a clinician sees it.
- **Imaging.** DICOM in, de-identified, preprocessed, segmented, reduced to nine named
  morphological features, scored by an ONNX model, and put through four more gates.

In both paths the model proposes and the gates dispose. Refusal is a success state, every
refusal carries a machine-readable reason, and every gate can be switched off to measure
what it was actually preventing.

Runs with `python3` and nothing else. No pip install, no network, no API key. The DICOM
parser, the image preprocessing chain, the ONNX serialiser and the inference interpreter are
all written from scratch here — which is how the no-dependency claim survives contact with a
computer vision pipeline.

```bash
make test        # 130 tests, including every safety gate and the ONNX Runtime parity check
make train       # generate the DICOM cohort, train the classifier, export models/lesion-mlp.onnx
make run         # end-to-end pipeline -> out/report.json, traces.jsonl, metrics.prom
make site        # build docs/index.html, the published inference control plane
make dashboard   # render out/dashboard.html from the last run
make api         # HTTP API on 127.0.0.1:8080
```

The published site at `docs/index.html` is generated by `scripts/build_site.py` from a live
pipeline run: the lesion images, gate ladders, attributions, trace waterfalls and every
figure on it were produced by code that executed seconds earlier. Nothing on it is typed in
by hand, so it cannot drift away from the behaviour of the repository.

## The measured result

Every number below is produced by `make run`, never written by hand.

| Metric | Value |
| --- | --- |
| Retrieval recall@4 | 0.929 |
| Retrieval precision@4 | 0.732 |
| Mean reciprocal rank | 0.964 |
| Answer rate on answerable cases | 1.00 |
| Mean groundedness of served answers | 0.933 |
| Citation coverage of served answers | 1.00 |
| Correct behaviour (answered vs refused) | **1.00** |
| **Unsafe answers served** | **0** |
| **Over-refusals on answerable questions** | **0** |

Those last two rows are reported separately on purpose. A single "accuracy" number lets a
system hide behind refusal: a copilot that answers nothing is perfectly safe and perfectly
useless. Unsafe answers are the clinical risk; over-refusals are the price paid to avoid
them. This build currently pays zero.

Evaluation set: 20 hand-labelled cases in `eval/goldset.json` — 14 answerable, 4
unanswerable (correct behaviour is refusal), 2 adversarial (prompt injection attempting
to extract a prescription).

### Red team: three generators built to defeat the gates

A safety layer that has only ever been tested against a generator that behaves is
untested. Each arm below is untrustworthy by construction and runs against the full gold
set, so **any** answer reaching a clinician is leakage.

| Arm | What it does | Blocked | Leakage |
| --- | --- | --- | --- |
| `ungrounded-control` | Confident, uncited prose from parametric memory | 20/20 | **0.00** |
| `numeric-tamper` | Verbatim guideline sentences, valid citations, **thresholds shifted** (6.0 → 4.9) | 20/20 | **0.00** |
| `polarity-tamper` | Verbatim guideline sentences, valid citations, **recommendation negated** | 20/20 | **0.00** |

The two tamper arms exist because the first version of this project had a real hole. Its
groundedness metric is token overlap against the cited chunk, and overlap is blind to
exactly the two edits that matter most in medicine: changing a number and inverting a
recommendation. *"Withhold spironolactone above 4.9 mmol/L [1]"* scores **0.97**
groundedness against a chunk that says 6.0, because every token except the number is
perfect. That is a plausible, well-cited, confidently wrong clinical threshold — the
worst possible output of a system like this, and the old gates served it.

So `nullius/verification.py` now checks the claim, not just the vocabulary: every numeric
literal in a sentence must appear in the evidence it cites, and a negation the sentence
introduces but its evidence lacks is a polarity conflict. Both produce their own refusal
reason and their own counter.

### Gate ablation: which gates are actually load-bearing

One gate removed at a time, every arm re-run. A gate whose removal changes nothing is not
protecting anything, and the only honest way to find out is to switch it off.

| Configuration | Leakage | Answers served | Over-refusals | Reading |
| --- | --- | --- | --- | --- |
| All gates on | **0** | 16 | 0 | Baseline |
| Without coverage gate | 1 | 18 | 0 | Off-topic answers start being served |
| Without citation gate | 0 | 16 | 0 | No incremental catch on this gold set |
| Without groundedness gate | 0 | 16 | 0 | No incremental catch on this gold set |
| Without numeric gate | **16** | 16 | 0 | Every fabricated threshold is served |
| Without polarity gate | **16** | 16 | 0 | Every inverted recommendation is served |

Two findings worth stating plainly rather than burying:

1. The numeric and polarity gates are doing the heavy lifting — 16 blocked leaks each — and
   the coverage gate is the only one whose removal changes what the *grounded* pipeline
   serves (16 → 18 answers, the two off-topic ones).
2. **The citation and groundedness gates show zero incremental catch on this gold set.**
   They are not useless — they fire first on the ungrounded arm and they are the only
   defence against a free-text model like `openai` that ignores the evidence entirely — but
   against these particular attacks the newer, stricter gates reach the verdict first. That
   is defence in depth, measured rather than assumed, and reporting it is more useful than
   pretending all five gates contribute equally.

`tests/test_nullius.py` asserts the ablation deltas, so a gate that is ever quietly
reduced to a no-op fails the build even while every other test still passes.

## Why this is not another RAG demo

### 1. Seven gates, and refusal is a first-class outcome

`nullius/copilot.py` will not emit text that fails any one of them:

| Gate | Blocks | Refusal reason |
| --- | --- | --- |
| **Retrieval** | Nothing above the BM25 score floor → refuse, never generate. | `no_retrieval_hits` |
| **Coverage** | Evidence that does not topically address the question. | `insufficient_query_coverage` |
| **Citation** | Any sentence without a marker resolving to a retrieved chunk. | `failed_groundedness_gate` |
| **Groundedness** | Sentences whose content tokens are absent from the evidence they cite. | `failed_groundedness_gate` |
| **Numeric** | Any dose, threshold or value not present in the cited evidence. | `unsupported_numeric_claim` |
| **Polarity** | A negation the sentence adds but its evidence does not support. | `polarity_conflict` |
| **Scope** | Prescriptive phrasing, rewritten into clinician-facing suggestions. | — (rewrites) |

The polarity check is deliberately **asymmetric**: it blocks negation the answer
introduces, but not negation it drops. Extracting *"review renal function"* from *"do not
continue without reviewing renal function"* is legitimate summarisation, and a gate that
fires on correct output is a gate that gets switched off in practice — which makes the
system less safe, not more.

The **coverage gate** is the one most RAG systems are missing, and it was found by the
evaluation harness rather than by intuition. Asked *"what is the ideal ventilator PEEP
setting for severe ARDS"* against a corpus containing no critical-care guidance, BM25
still returned the hyperkalaemia protocol — the two texts share the word "severe" — and
the generator produced a fluent, fully cited answer about potassium thresholds with a
groundedness score of **0.965**.

That is the most dangerous failure mode in retrieval-augmented generation: *high
groundedness against the wrong evidence*. Groundedness alone cannot catch it, because
the answer genuinely is grounded — in an irrelevant document. Relevance has to be gated
separately, so the top passage must now cover a minimum share of the question's own
terms, or of the patient's verified clinical signals for deictic questions like *"why is
this happening?"*. That change moved behaviour accuracy from 0.90 to 1.00 and unsafe
answers from 2 to 0.

### 2. Deterministic where determinism is safer

No model is involved in lab interpretation or drug safety. Reference-range
classification, least-squares trend slopes over each analyte's history, and missing-test
detection are ordinary code in `nullius/labs.py`; interactions are a curated table in
`nullius/interactions.py` where every rule carries a mechanism, an action, and a source.
An LLM is never asked whether two drugs interact — a hallucinated interaction, or a
missed one, is exactly what makes clinical AI unsafe. The table is incomplete, and says
so; invention would be hidden.

The demo patient reaches an **urgent** banner through eight independently derived
findings: potassium 5.9 mmol/L critical, three major interactions (lisinopril +
spironolactone, lisinopril + ibuprofen, ibuprofen with stage 3 CKD), and adverse trends
in creatinine, HbA1c, haemoglobin and eGFR — each traceable to a range or a slope.

### 3. Observability built as a first-class concern

`nullius/observability.py` implements OpenTelemetry-shaped spans with no dependency:
nested spans, trace ids, error recording, and a Prometheus text exposition endpoint. A
single `copilot.ask` produces a 7-span trace carrying retrieval scores, coverage,
groundedness, token counts and latency. Answers surface their own trace id, so any
clinical output can be reconstructed from the evidence up.

### 4. Access control and audit that cannot be bypassed

RBAC lives in `nullius/app.py`, not in the transport layer, so it applies identically to
the HTTP API and to direct library calls. Four roles (clinician, nurse, researcher,
auditor) map to explicit permissions; every patient read, question, refusal and denial
is written to an append-only audit table with actor, role, action, detail and trace id.

## API

Role arrives as a header; every route resolves it to a `Principal` before touching data.

```bash
curl -H 'X-User: dr.chen' -H 'X-Role: clinician' localhost:8080/patients
curl -H 'X-User: dr.chen' -H 'X-Role: clinician' localhost:8080/patients/pat-001/summary
curl -H 'X-User: dr.chen' -H 'X-Role: clinician' -X POST localhost:8080/patients/pat-001/ask \
     -d '{"question": "Why might this patient'\''s potassium be rising?"}'
curl localhost:8080/metrics    # Prometheus exposition
curl -H 'X-User: audit1' -H 'X-Role: auditor' localhost:8080/audit
```

Imaging routes require `imaging.read`, held by `clinician` and `radiologist` but not `nurse`:

```bash
curl -H 'X-Role: radiologist' localhost:8080/studies
curl -H 'X-Role: radiologist' localhost:8080/studies/stu-001
curl -H 'X-Role: radiologist' localhost:8080/studies/stu-001/preview.png -o frame.png
curl -H 'X-Role: radiologist' localhost:8080/vision/model
curl -H 'X-Role: radiologist' -X POST localhost:8080/vision/classify \
     -d '{"study_id": "stu-001"}'
```

`/studies/{id}/preview.png` returns the frame **as the model received it**, segmentation
outline included — not the original. Serving the original would hide preprocessing bugs; this
makes them visible. The study catalogue deliberately withholds ground-truth labels: an API
that hands out the answer key invites benchmarking against itself.

A nurse calling `/ask` or `/studies` receives 403 and the denial is audited.

## Limitations, stated plainly

These are deliberate scoping decisions, each recorded in `docs/ADRs.md`:

- **Data is synthetic.** Generated records, coded correctly but clinically simplified.
  Nothing here has been validated against real patients, and no metric on this repo
  should be read as clinical performance.
- **Groundedness is token overlap, not entailment.** It is a necessary condition, not a
  sufficient one: it can accept a sentence that reuses the evidence's vocabulary while
  inverting its meaning, and it penalises correct paraphrase. It is deterministic, free,
  and runs in CI, which is why it earns its place — with an NLI judge as the first
  upgrade (ADR-003).
- **The interaction table is curated, not licensed.** Five drug–drug and two
  drug–disease rules. Real deployment needs DrugBank or First Databank (ADR-007).
- **Retrieval is lexical.** BM25 handles the rare exact terms clinical queries are full
  of, but pure synonymy fails. The scorer is injected, so a vector or hybrid scorer
  drops in and must beat the measured baseline (ADR-005).
- **The risk score is declared, not fitted, and is not validated.** Sepsis, readmission and
  mortality *models* are still cut (ADR-006): trained on synthetic data they learn the
  generator and nothing about medicine. `nullius/risk.py` takes the other road — an additive
  log-odds score whose seven coefficients are written down in the source in the direction and
  magnitude KDIGO 2024 describes, with `validated: false` on every response. There are no
  outcomes in this cohort, so there is no AUROC for it and none is reported. What is real is
  the machinery around the number: abstention, provenance per input, and exact attribution
  (ADR-015).
- **Kafka, Spark and Kubernetes are deferred**, not forgotten. One writer and a thousand
  rows do not justify an event bus (ADR-001).
- **The imaging AUROC used to be 1.000, and that was a bug report, not a result.** The old
  generator drew benign and suspicious lesions from non-overlapping parameter ranges, so the
  classes were separable by construction and any classifier scored perfectly. The generator now
  samples severity from overlapping distributions with 6% label noise and 6/80 deliberately
  atypical cases. The honest number is **AUROC 0.878** on the held-out split (sensitivity 0.842,
  specificity 0.762 at the training-chosen operating point of 0.469). Real dermoscopy would
  still not behave like this; the figures worth reading are the refusal behaviours (ADR-013).
- **The pipeline's headline imaging numbers are computed on served studies only.** `report.json`
  shows AUROC 0.905 / sensitivity 0.938 / specificity 0.842 across the 35 of 40 test studies
  that passed the gates. That is *selective prediction*, and it flatters the model: the five
  abstentions are disproportionately the hard cases. Both numbers are published side by side
  precisely so the gap is visible rather than hidden.
- **No single imaging feature separates the classes, by design.** Recomputed on the current
  generator (`make separation`), the nine features span Cohen's *d* 0.42 to 1.85, and the best
  single feature — `asymmetry` — reaches only AUROC 0.894 alone. Under the old generator these
  numbers ran to *d* 9.7, which is what made the perfect AUROC possible. A test in
  `tests/test_explainability.py` now fails the build if any lone feature exceeds AUROC 0.99, so
  the generator cannot silently drift back into being trivially separable. The weakest feature,
  `variegation` (*d* 0.42), is kept and reported rather than quietly dropped — deleting the
  inconvenient feature after seeing the results is how an honest evaluation turns into a
  dishonest one (ADR-009).
- **Attribution is exact Shapley, not an approximation and no longer leave-one-out.** Both the
  imaging model (9 features, 512 coalitions) and the risk score (7 factors, 128 coalitions)
  enumerate every coalition, so the attributions provably sum to the difference between the
  patient's score and the baseline score. The measured efficiency residual is ~1e-16, i.e.
  floating-point noise, and it is asserted in the test suite rather than assumed. The earlier
  leave-one-out attribution double-counted correlated features; exact enumeration is only
  tractable here because the feature count is small, and the code says so.
- **The classifier is a 9→12→1 MLP over hand-computed features**, not a CNN on raw pixels. On
  80 synthetic images a CNN would learn the generator; the feature-based model is the honest
  choice at this data scale, and it makes every input to the decision nameable (ADR-009).

## Testing

`make test` runs 130 tests across ingest idempotency, lab classification and trend
direction, interaction detection, BM25 ranking, every copilot gate, RBAC enforcement,
timeline ordering, and the evaluation harness itself. The suite includes an assertion
that the grounded pipeline produces zero unsafe answers *and* zero over-refusals, that all
three red-team arms are fully blocked, and that removing the numeric or polarity gate
measurably increases leakage — so a regression in the safety gates fails the build, not just a
metric dashboard. CI additionally enforces explicit floors on recall, behaviour
accuracy, groundedness and citation coverage.

`tests/test_scope.py` exists because a green suite is not the same as a working system. A
cold-start probe — unzip, delete every generated artefact, ask questions the goldset never
asks — found three defects that all 86 tests had passed over, described in ADR-011. Each one
produced confident, fully cited, high-groundedness output, which is exactly the failure this
project claims to prevent. Those tests now ask the questions the goldset does not: questions
with no answer in the corpus at all.

The imaging half adds DICOM encode/decode idempotency, a check that de-identification leaves
no residual identifier and that pixels survive it intact, preprocessing determinism, Otsu and
erosion behaviour, ONNX round-tripping including refusal of unsupported operators and float64
tensors, each of the four imaging gates independently, and — the strongest single check in the
repository — **agreement between the hand-written ONNX interpreter and Microsoft's ONNX
Runtime on the same file to within 8.9e-08 across 200 random inputs.** That test is what turns
"I wrote a protobuf serialiser" into "I wrote a protobuf serialiser that is correct."

**Nullius assists a licensed clinician. It does not diagnose, prescribe, or replace
clinical judgement.**
